# Project Health Check — 2026-09-23

Gate: **Issue #29 — pre-analysis adversarial audit + repository sanitation**  
Direction: **SIMPLIFY**

## What this gate actually proved

Issue #29 did more than run green tests. It found repeated real enforcement
defects at source, baseline, event, parser, identity and operational-state
boundaries, and repaired them without requiring a broad P0/P1 model rewrite.

The surviving foundation can now:

- observe official source activity without calling it legal change;
- preserve complete prospective comparison state through partial route failures;
- distinguish Cellar ingestion actions from independently observed source state;
- bind VERIFIED authentic-cause evidence to the correct sealed Work/language;
- keep legal publication relevance separate from crawler/source timestamps;
- fail closed on ambiguous or unsupported legal conclusions;
- promote state with an executable cursor ownership rule;
- keep live network evidence separate from deterministic CI.

That is meaningful project value: the evidence model repeatedly caught errors
that a simpler “fetch, diff, summarize” implementation could plausibly hide.

It does **not** prove the public product is superior.

## What failed

### Broad novelty

The original broad differentiation space does not survive.

Monitoring, alerts, version history, structural diff, source corroboration,
grounded explanation, legal lifecycle/versioning, legal knowledge graphs,
semantic obligation extraction, text↔rule provenance, corrigenda analysis and
dependency/change-propagation all have strong existing precedents.

Needle may compose them more conservatively; it did not invent the categories.

### P2 as a feature ladder

Half-Life, Source Anomaly and Legislative X-Ray proved that the foundation can
support interesting derived views. They did **not** prove that the project
should keep creating new analytic primitives.

The project had begun to risk turning architectural expressiveness into its own
success metric.

### Raw operational output as a public feed

The latest audited operational window grouped 6,680 source events into 343 root
groups and produced:

- 0 verified legal-change cards;
- 10 audit cards;
- 333 abstention cards.

That is desirable fail-closed behavior. Surfacing that raw distribution as a
general-interest product would be mostly source-monitor noise.

Abstention and audit truth must remain inspectable, but visibility should depend
on context such as an opened source, evidence view, or explicit monitor.

## What survives

### Foundation

All frozen P0/P1 contracts remain in force.

The audit found implementation/enforcement defects, not a reason to replace the
identity, temporal, provenance, mutation, semantic, retrieval or Thread
ownership model.

### Core product questions

Two questions remain strong enough to justify continued product work:

1. **What changed, when does it legally matter, what proves that, and what is
   still unknown?**
2. **How did this rule become what it is today?**

Thread remains the natural answer to the second.

For the first, the next problem is presentation and comparative value, not more
ontology.

### Useful but non-roadmap capabilities

- Dependency Ripple / X-Ray remains a useful optional view over existing truth.
- Multilingual/corrigenda handling remains a correctness requirement and a
  plausible differentiator on difficult cases.
- Source Anomaly remains valuable trust/audit machinery.
- Half-Life v0.1 remains a valid derived demonstration.
- Change Atoms, procedure state, rule lineage and provenance remain internal
  correctness machinery unless a product question requires them directly.

## Complexity decision

No database, queue, object store, vector store, frontend framework or custom
model-training system is justified for the next horizon.

The current operational state file is roughly 3 MB. The latest report grew from
about 2.32 MB to 2.50 MB while baselines increased from 1,063 to 1,115 and
source observations from 2,341 to 2,543. Processed-event dedupe is bounded to
the replay horizon.

Baselines necessarily grow with observed Work/language coverage and the
file/GitHub pilot is not a forever store, but no current experiment has hit a
limit that justifies infrastructure. State size remains an explicit scaling
risk, not a pretext to solve hypothetical scale.

## Assumption changes

- The broad novelty assumption is rejected.
- Integrated evidence/legal-state discipline remains an **experiment in product
  differentiation**, not a novelty claim.
- Human-readable evidence presentation survives as the smallest product
  experiment.
- Positive non-impact/abstention survives as truth that must remain inspectable,
  but not as default public-news content.
- Half-Life v0.2 is parked.
- Further analytic-primitives work is blocked until comparative user value is
  demonstrated.

See `docs/assumptions.md` for the canonical live register.

## Reproducibility / privacy

The current project remains public-source safe:

- official/public EU material is the intended corpus;
- immutable source/provenance records carry hashes and observation identity;
- canonical outputs are versioned with code/fixtures;
- CI sanitation rejects common private key/container artefacts and repository
  hygiene failures;
- live network probes are separated from deterministic CI.

No private corpus or external-model dependency is required for the next
experiment.

## Next horizon

The next horizon is **comparative value proof**, not feature expansion.

Smallest first experiment:

> replace opaque “Source Mode” presentation with a human-readable
> **Evidence / Why this is shown** projection over existing provenance.

It must answer, without adding canonical truth:

- which official source supports this claim;
- what exactly that source supports;
- whether the support is direct, derived, source-only or unresolved;
- what does **not** follow from the evidence;
- which legal timing is established versus unknown.

The experiment then compares Needle against the strong simpler baseline on
difficult real cases where the legal-state distinctions matter.

Candidate discriminating cases already exist in the repository:

1. Regulation (EU) 2026/2104 — verified authentic mutation with publication
   known but application not established;
2. a language-scoped material corrigendum;
3. REACH dependency ripple — unchanged local Article 67(1), changed referenced
   Annex XVII;
4. a source-only/non-impact or context-required temporal case.

The goal is not “prettier cards”. It is to test whether a reader reaches a more
correct understanding because Needle preserves distinctions that the baseline
normally collapses.

## Kill condition for the next horizon

If the comparative cases do not demonstrate a recurring material understanding
advantage over direct EUR-Lex/strong change tools plus ordinary LLM explanation,
do not compensate by adding affected-entity models, ranking, more P2 analytics
or infrastructure.

At that point the project should redirect toward a narrower research/audit tool
or stop public-product expansion.

## Direction

**SIMPLIFY.**

Keep the evidence engine and the two core product questions. Freeze or park the
rest. Make the next increment prove user value before Needle earns any new
architecture.
