### Strong incumbent

If the owner already has an equivalent artifact/process, Candidate A can fail immediately.

### Market-access correction

The new sponsor rule matters:

> sophisticated evaluation infrastructure at a mature organization does not establish that a smaller legal-tech or legal-AI team has the same operational process.

But this correction does **not** create an internal value result.

The missing variables are owner-specific:

Those cannot be inferred from another public replay.

### Information-gain conclusion

Candidate A has no credible additional internal replay that would decide its value.

Another self-selected public maintenance event would mainly test structural coherence already established in #402.

Promotion trigger:

## Candidate C — failure/postmortem -> reusable regression/oracle

### What is already supported

Candidate C fits Needle's surviving asset unusually closely:

> a consequential known legal-AI failure becomes a maintained source-backed regression/oracle rather than a one-off incident note.

Prior evidence remains mixed and binding:

- #339 and #353 showed bounded failure-analysis usefulness;
- #349 showed a strong ordinary postmortem can already be sufficient;
- #362 found no stable generalized Needle artifact/discipline advantage;
- #400 therefore preserved C as a secondary candidate rather than promoting it.

### Incumbent subtraction: generic regression plumbing

Generic incident-to-regression mechanics are not a plausible Needle moat or access gap.

Current public Langfuse documentation shows an accessible workflow that can:

- add failed/interesting production traces to datasets;
- attach expected outputs;
- run repeatable experiments;
- compare revisions;
- run regression checks in CI;
- operate through a free account or self-hosted deployment.

Sources inspected 2026-09-27:

- https://langfuse.com/docs/evaluation/experiments/datasets
- https://langfuse.com/docs/evaluation/overview
- https://langfuse.com/docs

This does not prove every lean team uses such tooling.

It is enough to deny Candidate C novelty or value credit for generic:

- datasets;
- test-case storage;
- production-trace capture;
- experiment execution;
- regression CI;
- version comparison.

### Residual: legal-oracle conversion

The potentially distinct work begins **before** the generic regression system can safely store the test:

- what exactly failed legally;
- which authority/evidence owns the correction;
- which legal/evaluation time controls;
- which professionally valid alternatives must remain accepted;
- which opposite error must still fail;
- whether the failure changes an answer, criterion, acceptance boundary or result interpretation;
- whether prior outputs remain comparable;
- what uncertainty/adjudication remains unresolved.

Current Legal Benchmarks methodology is strong counterevidence to any claim that mature evaluators ignore this work. It uses lawyer-authored and lawyer-reviewed task criteria, admits multiple professionally defensible approaches, and escalates pass-changing disagreement to a qualified lawyer.

Source inspected 2026-09-27:

- https://www.legalbenchmarks.ai/methodology

So Candidate C cannot claim that mature incumbent practice lacks legal-oracle discipline.

### Market-access correction

The sponsor correction still leaves a real possibility:

> smaller legal-AI teams may have generic eval plumbing but lack a proportionate, reliable legal process for converting a real failure into a maintained oracle.

However public product documentation cannot establish:

- that this gap is prevalent in the target segment;
- that Needle's process reduces it;
- that the team's current postmortem is materially weaker;
- that a Needle-derived oracle package changes future release behavior.

The relevant unit is a **real incident owned by a real team**.

### Why another internal postmortem replay is rejected

A further public failure replay would be especially vulnerable to circular validation:

1. Needle selects a known legal failure;
2. Needle writes the strong baseline;
3. Needle writes the richer oracle;
4. Needle judges whether its own extra structure mattered.

The project already ran variants of this line through #339/#349/#353/#362.

Without an independent incident owner, current process and acceptance decision, repeating it would mostly search for another favorable case.

Promotion trigger:

> **one real legal-AI failure owner + the team's current postmortem/regression process + an accepted oracle/regression decision**, under sponsor-authorised access.

A newly available independently owned public incident could also reopen C only if it includes enough external maintenance/acceptance evidence to avoid Needle self-grading.
