## Trigger

#362 was deliberately designed to prevent the project's conditional-value story from
becoming unfalsifiable.

It predeclared an external temporal condition before row inspection:

- one ChronoLex-TW `Shifted` item;
- one mechanically matched same-statute `Stable` control.

The result was:

> **CONDITIONAL_HYPOTHESIS_NOT_SUPPORTED**

with:

- `DISCIPLINE_DELTA = NO`;
- `ARTIFACT_DELTA = NO`;
- `V0.2_NAVIGATION = NOT_NEEDED`.

The important finding was structural:

> the externally defined changed-law condition did not order the legally consequential
> oracle-maintenance burden in the predicted direction.

The Shifted row's later article amendment was not materially answer-determinative.

The Stable row required the richer substantive/procedural/case-law reconstruction.

Excellent ordinary evaluator-maintenance practice absorbed all consequential work in both.

## Mode comparison

### CONSOLIDATE / REDIRECT — selected

The project now has:

- bounded positive observations (#339, #353);
- bounded strong-baseline nulls (#349, #362);
- an external-job campaign (#359/#361) that supports a real evaluator/oracle-maintenance
  problem but contracts the distinct Needle contribution to method-level discipline;
- no demonstrated external need for the full corpus/Reference Pack as an operational
  dependency;
- no reliable pre-result selector for when Needle adds incremental value.

Continuing to search for a better "complexity" proxy would be result-seeking unless an
independent external trigger first justified that proxy.

The useful discipline does not need to disappear.

It can remain inside ordinary project practice:

> strong source-linked baseline first; preserve consequential legal-state,
> authority/boundary and reuse distinctions where they actually matter.

What should stop is treating external packet/artifact value as a standing proof programme.

### USE — operational incremental-value test

A case-selection-independent test would be materially better than another favorable-case
search.

The credible outcomes would need independent measurement of something such as:

- reconstruction time;
- missed consequential boundaries;
- handoff/reopening burden;
- regression-maintenance burden.

The current execution environment cannot measure those independently without substantial
self-grading or post-hoc scoring.

Creating a model/human relay merely to keep this hypothesis alive would itself require a
new experimental justification.

**Not selected.**

### DISCOVER — external adoption/demand

Direct evidence would be useful if it existed:

- repeated external pack use;
- external consumers requesting the failure-analysis contract;
- observed switching/adoption;
- measured repeated evaluator-maintenance burden.

Benchmark papers, legal-AI tools and public repositories are not that evidence.

The project currently has no direct external adoption signal strong enough to justify a
new demand-discovery programme.

**Not selected.**

### REVIEW / RELEASE

Reference Pack v0.2 already solves the demonstrated navigation problem.

#362 did not identify a release defect.

No v0.3, structured external-failure layer or software surface is earned.

**Not selected.**

### MAINTAIN

The most plausible orthogonal maintenance concern is issue-backed evidence-owner
mutability.

But #306 already tested it:

- 45/81 cases are issue-only;
- fingerprints could detect drift but not recover the old state;
- Git-backed snapshots would recover state but create duplicate truth/maintenance burden;
- no concrete consumer need earned snapshots.

The new contraction of external artifact-value evidence makes that heavier preservation
surface no more justified than before.

No new correctness/integrity trigger exists.

**Not selected.**

## Re-entry conditions

External artifact-value research may reopen only from a changed boundary such as:

- an actual external consumer repeatedly using/requesting the pack;
- measured reconstruction/handoff burden that strong ordinary practice fails to solve;
- a materially changed intended use;
- an independent evaluation setup capable of measuring operational delta without
  self-grading;
- a new external workflow where corpus/pack dependence is observed rather than inferred.

Do not reopen because another potentially favorable example exists.

No corpus/class, pack, license, product or scientific result changes in #364.
