Result: **Method wins this case for now.**

## Schrems II — Core catches itself

This is the most interesting negative.

Judicial Holding v0.1 can represent:

> Privacy Shield Decision 2016/1250 is INVALID.

It cannot honestly represent:

> examination of Decision 2010/87 disclosed nothing to affect its VALIDITY.

The current holding vocabulary is:

- INVALIDITY;
- INTERPRETATION.

Calling the second holding INTERPRETATION would be ontology laundering.

The regression deliberately proves that a VALIDITY candidate fails the current
schema.

That is evidence **against** Full/Core ontology completeness.

The Method has no difficulty stating both holdings correctly.

## Common charger — modest Core value

Two scoped APPLICATION START assertions support deterministic repeated queries:

- non-laptop covered category on 2025-01-01 -> active;
- laptop on 2025-01-01 -> inactive;
- laptop on 2026-04-28 -> active.

For one question this is overkill.

For repeated date/category queries, persistence starts to earn itself.

## Dutch AI Act corrigendum — strongest Core result

This is where the persistent representation is materially useful.

The existing language-scoped mutation contract stores:

- NLD scope;
- correction publication date;
- exact before text;
- exact after text;
- non-listed language = NO_ASSERTION.

A future investigator does not have to rediscover the historical wording from
scratch.

This is a genuine reproducibility/history advantage over Method alone.

## Interim result

Core is neither unnecessary nor generally necessary.

It appears strongest where the question is:

- historical;
- repeated;
- stateful;
- cross-time;
- cross-language;
- or intended for later machine querying.

It appears weak for one-off interpretive questions where careful source reading
already closes the issue.

And importantly, the gate itself found one Core ontology gap instead of giving
Core a perfect score.
