# Source ingestion contract v0.1

**Status:** adopted foundation rule  
**Date:** 2026-09-20  
**Origin:** live Cellar contract probe

## Purpose

Define how Needle moves from a public EU identifier to raw source bytes without conflating publication infrastructure, language expressions, file manifestations, and legal-text state.

## Live probe evidence

Controlled works:

- `32004R0794` — Commission Regulation (EC) No 794/2004.
- `31958R0001` — Regulation No 1 (1958), language regime.

Both were probed against the official Cellar dissemination interface from GitHub Actions.

### CELEX → Cellar work resolution

Both CELEX resource URIs returned HTTP 303 redirects to Cellar work resources.

Observed work IDs:

| CELEX | Cellar work |
|---|---|
| 32004R0794 | 26f403d1-7656-4c91-9726-c08d466ff8bd |
| 31958R0001 | 115852e8-30ac-496e-8015-d580366ff059 |

This validates CELEX as a viable public starting identifier.

### Language expression resolution

An English branch-notice request resolved to:

| CELEX | English Cellar expression |
|---|---|
| 32004R0794 | `.0006` |
| 31958R0001 | `.0008` |

**Invariant:** numeric Cellar expression suffixes must never be treated as a globally stable language code. Resolve language from metadata every time.

### Manifestation retrieval contract must be version-aware

The first probe used `Accept: application/xml;type=fmx4`, an older interface form still visible in legacy Cellar interface material. That request returned 404 for both controlled works.

The current Publications Office documentation instead specifies publication retrieval using:

- `Accept: application/list;mtype={manifestation-type}`
- `Accept: application/zip;mtype={manifestation-type}`

with `Accept-Language` selecting the expression.

The branch metadata itself exposes manifestation types including FMX4 for historical material, so the earlier 404 **must not be interpreted as evidence that FMX4 is absent**.

**Invariant:** the source adapter follows the current official dissemination contract and enumerates metadata before interpreting a failed representation request. Legacy negotiation forms may be retained only as compatibility probes.

### Manifestation regeneration is not legal mutation

The XHTML manifestation returned for the 2004 act contains a converter-generation marker from 2026.

This proves that an old legal work can acquire regenerated bytes without any corresponding legal amendment.

Therefore Needle must distinguish:

1. **legal text state** — the rule-bearing text at a legally relevant state/date;
2. **expression state** — a language expression of the work;
3. **manifestation state** — a rendered/encoded representation;
4. **observed artifact** — exact bytes retrieved at a particular time.

A manifestation/raw-byte hash changing is a provenance event, not automatically a legal mutation.

## Required ingestion sequence

```
INPUT IDENTIFIER
   │
   ▼
RESOLVE WORK
(CELEX / ELI / Cellar equivalence)
   │
   ▼
FETCH METADATA NOTICE
   │
   ├── expressions / languages
   └── manifestations / formats / streams
   │
   ▼
SELECT REPRESENTATION
using explicit preference + fallback policy
   │
   ▼
FETCH RAW CONTENT STREAM(S)
   │
   ▼
HASH + STORE OBSERVATION
   │
   ▼
PARSE / NORMALIZE
   │
   ▼
NORMALIZED LEGAL TEXT
   │
   ▼
COMPARE LEGAL STATES
```

## Representation selection policy v0.1

Selection is metadata-driven.

Preference order is provisional and subject to Gold Corpus testing:

1. structured legal XML carrying sufficient hierarchy;
2. XHTML/XML preserving legal hierarchy;
3. HTML where structurally usable;
4. PDF only when no trustworthy structured representation exists.

Do not hardcode a single MIME type as universally canonical.

If several official structured manifestations exist:
- preserve all discovered identifiers;
- select one parser input according to explicit adapter policy;
- record the selected manifestation and why;
- retain ability to cross-check against another official manifestation.

## Source observation record

Every downloaded artifact should store at least:

- work identifier(s);
- expression identifier + language;
- manifestation identifier + MIME/format;
- content-stream identifier;
- requested URI;
- final URI;
- redirect chain;
- retrieval timestamp;
- response content type;
- byte length;
- raw SHA-256;
- adapter/parser version.

The raw hash proves what Needle observed. It does **not** prove legal novelty.

## Change-detection implication

Needle needs two distinct diff layers:

### Artifact diff
“Did the bytes or publication representation change?”

Possible reasons:
- re-rendering;
- converter update;
- metadata republishing;
- actual legal correction/change;
- source-system migration.

### Legal-text diff
“Did normalized legally meaningful text change?”

Only this layer may generate candidate legal mutations, subject to provenance and status checks.

## Efficiency implication

Live probes showed that full RDF tree notices can be very large (roughly 14–21 MB for these examples), while language branch notices were roughly 1.2–1.35 MB.

Initial adapter design should therefore avoid fetching full tree notices for every routine operation when a narrower branch/object notice is sufficient.

Full tree retrieval remains useful for:
- discovery;
- audits;
- relationship reconstruction;
- difficult historical cases.

## Current foundation verdict

**Cellar remains the preferred ingestion backbone, with metadata-first manifestation discovery and contract-tested retrieval.**

The simplistic “CELEX → assume one fixed retrieval header forever” path is rejected.

## New invariants

### A manifestation is a bundle, not necessarily a file

The 2004 FMX4 manifestation has 132 content streams. Needle must preserve the WEMI hierarchy:

```
Work
  └─ Expression
      └─ Manifestation
          ├─ Item / content stream
          ├─ Item / content stream
          └─ ...
```

Parser input cannot assume one source artifact per act or per manifestation.

### Representation capability is expression-scoped

Availability of FMX4/XHTML/HTML must be resolved for the chosen language expression. The presence of an FMX4 manifestation elsewhere in a large notice does not prove FMX4 availability for the target expression.

### Fallback is a normal path, not an error path

For early material, HTML may be the best available official machine-readable expression. That should carry an explicit representation-quality class rather than being treated as an ingestion failure.

Provisional representation classes:

- `STRUCTURED_LEGAL_XML`
- `STRUCTURED_XHTML`
- `STRUCTURED_HTML`
- `PDF_TEXT`
- `PDF_IMAGE`
- `OTHER`

The class records parser capability; it is not a judgment about legal authority.
