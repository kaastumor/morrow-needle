## Trigger

#331 changed Needle's public identity in a material but bounded way.

The project now describes itself as:

> **adversarial legal-research known-failure reference corpus + exposed regression
> fixtures + minimal evaluation discipline**

The key durable boundary is:

> **reference status is corpus-wide; regression status is case/fixture-specific.**

That clarification is externally supported. It does not itself establish that the
reference corpus has meaningful residual value.

## Current evidence that constrains allocation

Three results matter most.

### #214 — hard diagnostic null

Supplying the corpus/index treatment did not produce latent diagnostic/correctness rescues
over the strong source-grounded baseline in the frozen pilot.

Therefore no next task may assume the corpus is valuable because it improves answer
accuracy or hidden-trap detection.

### #327 — first real post-answer USE null

One mechanically selected current EU legal-information task was solved completely by
ordinary official-source research.

The later Reference Pack pass added only analogy/terminology.

Therefore no next task may assume generic post-answer pack use is already demonstrated.

### #331 — role clarification

External practice supports known/exposed failures as sources for regression engineering,
but operational regression artifacts normally preserve runnable inputs, expected behavior
and evaluators.

Therefore:

- the full corpus is a known-failure reference asset;
- executable regression is fixture-specific;
- building an 81-case executable layer merely for symmetry would be post-hoc engineering.

## Mode comparison

### REVIEW / RELEASE — executable subset

This is the most tempting next move.

The ten revealed EVALUATION cases already preserve strong historical execution contracts,
and the four metamorphic relations are genuine derived regression engineering.

A compact executable subset would therefore be technically feasible.

**Why not now**

Feasibility is not a use requirement.

No evidence currently shows that an external consumer needs:

- one manifest over the ten evaluation cases;
- a runner;
- normalized grading;
- another release artifact.

#327's first real pack-use observation was a null, not a request for better execution
packaging.

Building the subset now would risk **mimicry-driven implementation**:

> external eval systems have executable datasets, therefore Needle should package one.

That reverses the project's complexity rule.

**Allocation: not selected.**

### USE — rerun one exposed regression fixture

This is also credible.

A revealed evaluation case could be rerun as a known-case regression without any claim of
fresh validation.

**Why not now**

A single current rerun would answer whether one preserved fixture remains executable, but
#311/#331 already establish that the exact evaluation contracts exist.

Without a concrete changed model/application, consumer or release gate that needs the
regression result, the run would mainly demonstrate that a known runnable artifact can be
run.

That is lower information gain than resolving whether the broader reference asset has a
distinct external job at all.

**Allocation: not selected now.**

### CONSOLIDATE

The identity repair has already been reconciled across:

- README;
- charter;
- corpus documentation;
- value evidence;
- backlog.

Reference Pack v0.1 is deliberately frozen as historical release state.

There is no live ownership conflict requiring another consolidation pass.

**Allocation: not selected.**

### MAINTAIN

No new security, integrity, cost or correctness trigger exists.

The regression/reference terminology change did not break corpus validation, and the
normal unit/sanitation gates passed.

**Allocation: not selected.**

### DISCOVER — external residual-value / substitute test

This is the highest-information next mode.

#331 answered:

> what kind of external artifact is Needle?

It did **not** answer:

> why should such an artifact exist as an external reference corpus rather than just as a
> project's internal failure archive?

That distinction is now the central project-value uncertainty.

Strong substitutes exist:

- public legal benchmarks with source/rubric support;
- legal-AI failure and hallucination taxonomies;
- source-linked issue/postmortem records;
- general AI incident/regression-memory practice.

If those alternatives losslessly perform the same evidence/provenance/reconstruction job,
Needle should contract again.

If Needle retains a residual job, that job should become the next explicit use contract
rather than an implied value claim.

**Allocation: selected.**

## Why this is not competitor-exists -> useless

#335 must apply the post-#282 residual-value rule.

The existence of:

- LegalBench;
- DELTA;
- hallucination/error taxonomies;
- incident databases;
- ordinary project postmortems

is not itself a rejection.

The test is whether the strongest realistic combination of those alternatives preserves
the same consequential job without material loss.

Needle survives only if a concrete residual remains, such as:

- unusually reconstructable evidence lineage;
- explicit historical/source-state preservation;
- reusable positive + boundary/negative evidence around failure mechanisms;
- reliable conversion from an observed legal failure into later regression engineering.

Those are hypotheses, not assumed strengths.
