# Issue #86 — Full Needle result

The surprising part of the gate is not that the strong baseline did well.

We already knew that from Issues #49 and #59.

The stronger result is:

> **Full Needle did not beat Needle Core on any of the five unseen cases.**

That includes a case where Core itself failed to represent the complete answer.

Why?

Because the higher-level product/read-side surfaces do not magically repair
canonical gaps.

They mostly still consume the earlier Thread-era object family.

The repository therefore contains more architecture than the current essential
project identity needs.

This is not a deletion order.

It is a change in burden of proof.

From now on:

- Method is the primary contribution candidate;
- Core persists only where state/history/repeatability earns it;
- every projection is optional until a concrete research problem needs it.

That is the smallest identity consistent with the evidence so far.
