# Methods and operating-system history

Status: **DURABLE METHOD MEMORY**

Needle produced not only legal models and code, but a distinctive research operating discipline.
Some of the most valuable project capital is methodological.

## 1. Strong boring baseline

Every value claim is compared with the strongest realistic alternative, not a crippled control.

Depending on the job this includes:

- authentic/official EU and national sources;
- mature doctrine;
- mature change/version tools;
- ordinary source-linked notes;
- a capable source-grounded model with comparable access.

This rule was central to the project's contractions and should remain non-negotiable.

## 2. Real adversaries before architecture

Foundation contracts were repeatedly earned by real official cases rather than synthetic elegance.

Pattern:

1. name a simplifying assumption;
2. find an official case likely to break it;
3. try the smallest existing owner;
4. if the owner distorts the truth, introduce the narrowest new contract;
5. leave a regression and explicit forbidden inference.

Examples:

- provision identity -> immutable instances + lineage;
- temporal day precision -> Temporal v0.2;
- horizontal-only space -> vertical legal extent;
- text-only state -> dynamic sets/metrics/findings/judicial holdings;
- public-origin-only determinations -> recognized private determinations.

## 3. Fail closed

Across parsing, identity, time, evidence and evaluation:

- unresolved remains unresolved;
- absence is not negation;
- source route failure is not document absence;
- structural similarity is not legal lineage;
- later event does not synthesize an earlier end date;
- a current consolidation does not prove historical source state;
- a model-only hypothesis never becomes authoritative through confidence.

This is a deeper project principle than any particular schema.

## 4. Singular ownership

One consequential kind of truth has one canonical owner.

Examples:

- source observation != legal mutation;
- temporal state != text state;
- authoritative metric != metric rule evaluation;
- categorical finding != legal geometry;
- judicial holding != textual amendment;
- external private determination != public-law recognition of that determination.

This principle prevented the old system from becoming one giant universal ontology.

## 5. Gold Corpus and negative expectations

The Gold Corpus introduced two important ideas:

- machine-readable positive expectations;
- machine-readable **FORBIDDEN_INFERENCE** expectations.

That second part is especially important. Needle tests not only what the system must say, but what
it must **not** infer.

## 6. Derivation versus evaluation exposure

A case used to discover a mechanism cannot later be treated as fresh blind validation of that same
mechanism.

Revealed cases become regression/reference evidence.

Current corpus exposure rule:

> all cases exposed; blind reuse false; future use `REGRESSION_ONLY`.

## 7. Surfaced versus latent trap detection

#95's correction created a lasting construct distinction:

- **SURFACED_TRAP_ADJUDICATION** — prompt identifies/cues the dangerous distinction;
- **LATENT_TRAP_DETECTION** — realistic prompt leaves the hidden failure mechanism unstated.

This prevents the project from calling correct resolution of a named trap 'detection'.

## 8. Seal-before-execution discipline

For decisive comparative experiments, Needle developed:

- frozen exact prompts/questions;
- precommitted answer/evaluator keys;
- frozen arm instructions;
- frozen interpretation rules;
- cryptographic hashes;
- independent/fresh execution where required;
- no post-result case replacement;
- reveal/archive after completion.

Later audits strengthened the archival requirement because hashes without eventual plaintext/raw
artifacts are not full reproducibility.

## 9. Concrete failure events over synthetic scores

Needle often avoided decorative aggregate scores.

Useful outcomes included:

- wrong legal conclusion;
- status/application confusion;
- historical overwrite;
- source-origin/authority confusion;
- scope loss;
- unsupported certainty;
- false accept / false reject;
- inability to explain provenance;
- needless source reopening.

Numeric scoring is allowed only when the construct genuinely supports it.

## 10. Incumbent-first / existing-class first refusal

Especially after #214 and #282:

- first ask whether mature doctrine/current systems already own the law;
- then ask whether an existing Needle class already captures the consequential regression distinction;
- only then consider a new class/contract.

Canonical formulation:

> **Existing is not useless. Different is not valuable. Novel is not demanded.**

This rule is symmetrical:

- familiarity does not automatically kill regression value;
- novelty does not automatically create it.

## 11. Anti-growth / compression discipline

Corpus breadth was repeatedly challenged by:

- targeted overlap audits;
- coverage gates;
- class compression;
- generality tests;
- composition tests;
- negative controls;
- explicit `NO_EXISTING_CLASS_MATCH` permission.

#244 actually removed three class pairs. Later audits refused forced merges when the consequential
distinctions were not losslessly redundant.

## 12. Research mode binding

#282 found that mode changes could drift silently.

Repair:

> a selected mode/horizon remains binding until completed or explicitly superseded by another gate.

This matters because otherwise an attractive new case can silently undo a prior depth/compression
decision.

## 13. WIP=1

WIP=1 is a concurrency discipline:

- one active consequential work item;
- finish/reconcile before moving on.

Later governance audits clarified that WIP=1 does **not** prove that another work item must exist.

## 14. Sponsor continuity and the 'never idle' correction

The sponsor repeatedly instructed Morrow to remain active, autonomous, structured and creative,
and explicitly rejected `IDLE BY DESIGN` as an excuse for inaction.

Early governance translated that too literally into:

> finish -> always select another bounded research question.

This created risk of serial experiment generation.

Later correction:

- sponsorship means continued ownership/responsiveness;
- stop weak hypotheses;
- do not manufacture activity;
- active work requires a justified goal/evidence/maintenance obligation/sponsor objective;
- an explicit `EVIDENCE_GATED / COMPLETED_FOR_CURRENT_EVIDENCE` state is legitimate.

This preserves the sponsor's actual intent: **no lazy idling, but also no fake progress**.

## 15. Purposeful operating modes

Governance eventually separated:

- DISCOVER;
- CONSOLIDATE;
- USE;
- REVIEW-RELEASE;
- MAINTAIN;
- EVIDENCE_GATED / COMPLETED_FOR_CURRENT_EVIDENCE.

This is better than treating research as the only legitimate form of progress.

## 16. Evidence-triggered discovery

After the Corpus Explorer technical MVP, the project experimented with a structured discovery lane.

Useful features:

- compact entry point;
- selective context loading;
- resumable handoffs;
- bounded searches;
- counterexample checks;
- strongest alternative first;
- separate exploration from confirmation;
- explicit stopping rules;
- value/usability/feasibility/viability plus evidence validity;
- no feature implementation merely because a discovery idea exists.

Cycle 1 showed this could produce useful allocation decisions, but standing continuous discovery
was not granted automatic status because of process overhead.

## 17. Step-back reviews

Repeated sponsor guidance required Morrow to:

- periodically zoom out;
- red-team assumptions;
- compare current work with project purpose;
- inspect whether process itself is creating selection pressure;
- treat negative results as useful progress.

Important examples:

- post-P1 foundation audit;
- #84 wide-angle system audit;
- #196 project setup review;
- #282 research retrospective;
- #288 constitutional/governance audit;
- #375 pre-partner reality honing;
- #398 audit-derived MVP readiness repair.

## 18. Actions/cost discipline

The project discovered that too many narrow GitHub workflows and repeated polling created unnecessary
cost/churn.

Rules developed:

- batch coherent commits;
- use one late CI check rather than repeated polling;
- permanent workflow must own a unique responsibility;
- live probes are manual unless operational evidence demands scheduling;
- avoid Git as a live database;
- preserve expensive historical evidence without keeping the mechanism permanently running.

## 19. External evidence boundaries

A major late-stage methodological distinction:

Internal work can establish:

- coherence;
- representational fit;
- reproducibility;
- baseline overlap;
- falsifiers;
- implementation feasibility.

Internal work cannot honestly establish:

- buyer acceptance;
- real incumbent burden;
- willingness to pay/use;
- actual qualified-expert savings;
- repeat-use behavior.

This is why Candidate A now has a hardened internal core **before** external validation, rather than
either reaching out too early or pretending internal replay proves value.

## 20. What methods should never be forgotten

If only a short list survives, preserve these:

1. Sources outrank models.
2. Strongest boring baseline first.
3. Real adversary before architecture.
4. One owner per kind of truth.
5. Positive and forbidden inferences are both regression targets.
6. Derivation is not fresh validation.
7. Surface/adjudication is not latent detection.
8. Freeze the decision rule before seeing results.
9. Negative/null results shrink claims; they do not disappear.
10. Existing is not useless; different is not valuable; novelty is not demanded.
11. WIP=1 controls concurrency, not existential project activity.
12. Preserve parked capability without letting it drive architecture.
13. External user value must eventually be measured in the user's real workflow.
