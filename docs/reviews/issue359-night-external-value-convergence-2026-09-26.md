# Issue #359 / campaign #361 — external evaluator-job convergence

Date: 2026-09-26  
Disposition: **EXTERNAL_DISCIPLINE_VALUE_SUPPORTED; FULL_PACKET_JOB_UNPROVEN**

## Trigger

#357 consolidated the conditional use contract:

> **Strong source-linked postmortem first. Full Needle packet work is earned only when
> consequential reusable legal relationship/state/boundary/reuse structure remains to
> formalize.**

#359 then asked whether the project had become too packet-centric and whether the next
information gain should come from a real external evaluator/maintainer job rather than
further packet refinement.

Campaign #361 executed eight read-only scheduled research slots against that question.

The scheduled controller was intentionally read-only after scheduled GitHub writes proved
unreliable. This document is the interactive reconciliation of those results.

## Night result

The campaign supports a narrower conclusion than:

> external evaluators need the Needle packet.

The supported conclusion is:

> **Needle-style failure-analysis discipline can add value on some legally complex
> evaluator/oracle-maintenance tasks, especially where a strong ordinary postmortem still
> leaves consequential legal-state, authority-relationship, boundary, provenance/reuse or
> regression-oracle structure to preserve.**

What remains **unproven** is that an external consumer needs:

- the full Needle artifact;
- the 81-case corpus as an operational dependency;
- Reference Pack v0.2 as a maintained external workflow dependency;
- a dedicated Needle software/product surface.

The same discipline may sometimes be absorbed into good professional benchmark/postmortem
practice without adopting Needle as an artifact.

## Run 01 — direction

The wide-angle review selected:

> **DISCOVER — EXTERNAL CONSUMER / EVALUATOR JOB**

Reason:

- the recent chain had become packet-centric;
- further self-description had lower information gain than testing whether an external
  evaluator/maintainer job exists;
- another release iteration was not earned.

## Run 02 — external job evidence

A conditional external job survived:

> maintaining trustworthy legal evaluation/oracle artifacts when model failure, retrieval
> failure, source-state error and benchmark-ground-truth error can be confused.

Strong incumbents already provide:

- dataset versioning;
- evaluation harnesses;
- source-linked issue/postmortem workflows;
- rubric/answer-key maintenance;
- ordinary regression tests.

The external need is therefore not "failure memory" in general.

The potentially distinct job is preserving the **legal reason the oracle is valid**, its
authority/source-state boundaries and safe future reuse when those facts are non-trivial.

Disposition:

> **EXTERNAL_JOB_SIGNAL — CONDITIONAL**

## Run 03 — strongest substitute attack

After giving incumbent evaluation/postmortem practice its strongest realistic form, most
of the proposed job disappeared.

A narrow residual survived where repairing an evaluator requires legal reconstruction
rather than ordinary data hygiene:

- proposition-specific authority state;
- legally consequential distinctions;
- opposite-error/boundary controls;
- source/version state;
- regression reuse conditions.

The night used LaborBench's documented ground-truth correction as a useful example:
correcting omitted qualifying legal state materially changed a published STARA result.

Disposition:

> **RESIDUAL_VALUE_CONTRACT — NARROW**

## Run 04 — real/falsifiable use

The LaborBench SEA correction supported the residual at the **method level**.

The useful work was preserving a distinction of the general form:

> **ACTIVE ≠ AUTHORIZED_ONLY ≠ FUNCTIONALLY_EQUIVALENT**

The important contribution was not a Needle class match.

It was keeping the benchmark-oracle repair from collapsing legally different states when
turning the correction into reusable evaluator/regression logic.

A sufficiently strong ordinary postmortem could still absorb that discipline.

Disposition:

> **CONDITIONAL_RESIDUAL_VALUE — SURVIVES, BUT METHOD-LEVEL**

## Run 05 — adversarial negative control

OpenContracts / LegalBench-RAG supplied the needed negative control.

Its impossible recall values were caused by dataset/annotation ingestion defects such as
duplicate/orphaned annotations.

Ordinary engineering repair was sufficient:

- cleanup;
- idempotent repair;
- regression tests.

No consequential legal-state reconstruction remained.

Disposition:

> **NEGATIVE_CONTROL_PASSES — CONDITIONAL BOUNDARY REPLICATES**

This matters because it rejects:

> every legal benchmark failure deserves a Needle packet.

## Run 06 — product/release implication

No new durable product/release surface earned itself.

Rejected:

- Reference Pack v0.3;
- structured external-failure database;
- maintained evaluator software;
- corpus growth;
- new regression platform.

Reference Pack v0.2 remains current/frozen.

Disposition:

> **NO_RELEASE_CHANGE — CONSOLIDATE_EXTERNAL_EVIDENCE_ONLY**

## Run 07 — adversarial convergence

The positive evidence survived only after contraction.

Main attacks:

1. **selection bias** — LaborBench is favorable to the Needle-style distinction;
2. **good-practice substitution** — the discipline may be ordinary excellent evaluator
   maintenance rather than a Needle-specific capability;
3. **job vs demand** — benchmark/oracle maintenance is real, but demand for Needle as an
   artifact remains unshown;
4. **unfalsifiable complexity risk** — positive cases cannot simply be called "complex"
   after the fact;
5. **corpus-vs-method ambiguity** — recent positive evidence supports a discipline more
   directly than it supports operational dependence on the frozen corpus;
6. **no measured operational gain** — time saved, errors prevented, handoff burden or
   regression-maintenance improvement has not been quantified.

Therefore the conclusion must not be:

> full Needle packet value is established for evaluator teams.

It is:

> **credible conditional method-level value; artifact-level incremental value unproven.**

## Red-team correction

The night conclusion is deliberately narrower than the initial morning synthesis.

The strongest currently supportable statement is:

> **There is credible evidence that Needle-style failure-analysis discipline can add value
> on some legally complex evaluator/oracle-repair tasks. It is not yet established that
> the full Needle artifact, its corpus, or its Reference Pack provides material incremental
> value to an external consumer over adopting equivalent good practice directly.**

That is now the operative external-value hypothesis.

## Next falsifier required

The conditional-value rule risks becoming unfalsifiable if a positive result is labelled
"complex" and a null labelled "simple" after the result is known.

The next test must therefore predeclare complexity **before** inspecting outcomes and give
ordinary professional practice every advantage.

Recommended design:

> **paired temporal-oracle maintenance test**

Use one externally labelled changed-law item and one stable-law control from the same
public benchmark, selected mechanically by published order before row inspection.

The hypothesis is directional:

> Needle should add more consequential reusable structure on the changed-law item than on
> the stable control.

The hypothesis is weakened if:

- the strong ordinary baseline already preserves all consequential changed-law state;
- Needle adds only labels/reformatting;
- Needle adds comparable "value" to the stable control;
- the artifact-level contribution cannot be separated from ordinary good evaluator
  practice.

No new release work should precede that falsifier.
