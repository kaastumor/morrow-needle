## Product hypothesis

The surviving Needle value can become materially more useful without reviving
the old architecture if the adversarial corpus is made directly browsable and
inspectable.

The MVP is a **thin static projection** over the canonical corpus + evaluation
protocol.

It is not a legal research engine.

## Primary user

A researcher, evaluator, legal-tech practitioner or future Needle contributor
who wants to inspect:

- what kind of legal-information failure a case captures;
- why the failure is consequential;
- whether evidence is derivation or evaluation;
- whether evaluation tested surfaced adjudication or latent detection;
- whether a case is exposed/regression-only;
- where the durable evidence lives.

## Core journey

1. Open explorer.
2. See corpus/evaluation summary.
3. Search/filter to a relevant failure family.
4. Open one case.
5. Understand the decisive trap and evaluation provenance.
6. Follow its issue/artifact references.
7. Navigate to related cases by existing trap-class membership.

## MVP technical acceptance

The technical candidate requires:

- every current canonical corpus case projects without hidden fallback;
- search/filter/detail/deep-link features work by implementation contract;
- evaluation/exposure concepts are explained accurately;
- fail-closed data/error path exists;
- accessibility/responsive baseline implemented;
- deterministic validations pass;
- CI either passes or qualifies under the narrow pre-step CI-degraded exception;
- `docs/mvp/v0.1-release-check.md` maps criteria to evidence.

Technical acceptance is not a claim that sponsor/user usability has been proven.

## Metrics

No product KPI dashboard is created for v0.1.

At MVP review record only directly useful observations:

- canonical cases visible / canonical cases total;
- structural projection failures;
- deterministic test failures;
- unresolved manual/browser acceptance;
- user/sponsor qualitative feedback once actually observed.

Do not create engagement metrics before there are real users.

## Release posture

No public deployment is required for MVP acceptance.

First prove the local/static product artifact. Hosting/deployment is a later
feature hypothesis unless the sponsor explicitly asks for it.
