# Project Health Check — post-Thread comparative gate

Date: 2026-09-23  
Direction: **STOP PUBLIC-PRODUCT EXPANSION; CONTINUE RESEARCH/AUDIT MODE**

## North-star result

Two successive comparative gates failed the project's own threshold for a
general public legal-change product:

- #49: four real live/change cases produced one initial loss, two parity cases
  and one plausible dependency-discovery advantage;
- #59: the strongest existing Thread case materially improves audit packaging
  and negative-evidence closure, but a careful official-source + capable-LLM
  baseline can reconstruct the same legal history.

The project should not respond by inventing more analytics or a narrower
novelty slogan.

## What the project is now

Morrow // Needle is an **evidence-first EU legal-change research and audit
engine**.

Its strongest demonstrated capabilities are:

- falsifying source/update assumptions;
- preserving evidence ownership;
- reconstructing legal time without collapsing dimensions;
- testing text versus semantic/rule change;
- discovering indirect dependency effects;
- retaining positive non-impact and explicit unknowns;
- producing provenance-closed legal histories;
- maintaining executable regressions for discovered legal-information traps.

## What is no longer an active objective

- a general-interest “what changed?” news product;
- broad end-user subscription/ranking UX;
- a public product moat based on legal-informatics novelty;
- product-scale storage/frontend infrastructure;
- analytics expansion for its own sake.

Existing public-card/Thread projections stay because they are useful audit
views and regressions. They are not an implied roadmap.

## Complexity decision

No deletion campaign is justified. The current source monitor, operational
pipeline and projections continue to generate adversarial evidence and exercise
the foundation.

No new architecture is justified either.

Future work should begin from a **specific research/audit question**, preferably
one capable of falsifying a legal-information assumption, and should leave a
fixture, finding, regression or bounded negative result.

## Research-mode success condition

A run is valuable when it produces at least one of:

- a verified legal-history finding;
- a source/metadata contradiction;
- an evidence-ownership defect;
- a temporal or dependency trap;
- a useful negative/non-impact conclusion;
- a regression preventing a previously demonstrated error;
- a clear finding that a proposed distinction adds no value.

The project no longer needs every result to imply a public feature.

## Reopen rule for public-product work

Public-product expansion may be reopened only when external/user evidence
identifies a recurring concrete problem for which the strong baseline
(EUR-Lex / mature change tools / direct official sources / capable LLM) fails in
a material way.

Do not manufacture such a problem from the architecture.

## Direction

**STOP PUBLIC-PRODUCT EXPANSION. CONTINUE RESEARCH/AUDIT MODE.**
